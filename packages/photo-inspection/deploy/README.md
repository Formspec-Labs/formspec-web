# Runtime deployment and qualification

This is a reviewed deployment candidate. Web has not built an image, started a service, changed Source registration or qualified native resource isolation. Runtime owns those steps and records the image digest, configuration pins, resource observations and actual integration results before activation.

The image build requires an explicit `NODE_IMAGE` argument; select and record its immutable digest. Compose requires `PHOTO_PROVIDER_IMAGE` with an immutable digest, `PHOTO_PROVIDER_CONFIG_DIR` and `PHOTO_PROVIDER_RECEIPT_DIR`. Prepare public `config.json`, `policy.json` and `jwks.json` in the read-only config directory. The receipt directory must allow uid/gid 1000 to append. Keep credentials outside this public configuration: the adapter receives a dedicated Source bearer token and only retains public issuer signing keys.

The config follows `schemas/provider-config.schema.json`. Pin Source’s full public registration descriptor and full serialized FormVersionRecord with plain RFC 8785 canonical JSON SHA-256, prefixed `sha256:`. Pin the policy the same way; pin JWKS and the output schema by raw bytes. These hashes do not use Response handoff or signing framing. The test helper creates controlled fixtures; it is not a production config generator or a published D1 document.

Compose proposes a read-only root, non-root uid, no added capabilities, no-new-privileges, private cgroup namespace, 512 MiB memory with no swap, 64 processes, one CPU and no automatic restart. The handler checks the corresponding Linux files and refuses startup or requests when checks fail. Qualify the actual namespace, read-only cgroup mount, decoder membership, cancellation/reaping, memory exhaustion and process/concurrency behavior. The checks alone do not prove immutability or a mathematical bound without temporary kernel overshoot. [Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) describes the kernel’s memory and swap behavior.

The internal network exposes port 8080 without publishing a host port. Runtime must connect Source through an explicitly reviewed network and fixed HTTPS endpoint, or use the explicitly allowed literal development-loopback HTTP exception. Record that arrangement and exact matching registration endpoint. Never add an implicit HTTP or credential fallback.

Before Source selection, exercise actual token refusal, request/attachment integrity failures, missing-input Pending, diagnostic receipt persistence, timeout and quarantine/restart with the final image. Confirm that Source hydration accepts the committed DTO and preserves Save behavior. No result from this adapter is Qualified; Sign and Submit remain blocked wherever native evaluation requires Qualified facts. Visual-rule executors, module adoption and compliant-photo claims require separate work.

Quarantine returns 503 until restart. Restart only after diagnosing unfinished work and retaining its failure evidence. Receipt retention exhaustion also refuses requests; rotate or retain receipts deliberately before restarting. Diagnostic receipts contain hashes, timestamps, budgets and measurements, with no bearer tokens, raw images or raw owner records.
